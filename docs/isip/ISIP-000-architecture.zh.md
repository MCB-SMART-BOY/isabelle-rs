# ISIP-000：架构与可信边界

**ISIP 版本：** 草案 0.1
**状态：** 设计文档
**依赖：** 无（此为根规范）

## 1. 范围

ISIP-000 定义 ISIP 兼容证明平台的分层系统架构。它确立可信计算基（TCB）、依赖方向以及可信内核操作与不可信平台服务之间的边界。

## 2. 分层模型

ISIP 兼容系统**必须**至少组织为以下四层：

### Layer 0：可信计算基

TCB 是其正确性对定理可靠性不可或缺的组件集合。

**包含：** 定理类型、原始推理规则、已认证项/命题、理论祖先、证书检查器、`accept_closed_theorem` 操作。

**不得包含：** 异步运行时、数据库、网络 I/O、WASM、GPU 计算、AI 模型、LSP 处理器、JSON 序列化、会话状态、文档版本、证明搜索算法。

**依赖：** 仅限于密码学哈希（`sha2`）和错误处理（`thiserror`）。在 Isabelle-rs 中，这是 `isabelle-kernel` crate。

**零警告策略：** TCB **必须**在 `RUSTFLAGS="-D warnings"` 下零警告编译通过。

### Layer 1：逻辑后端

负责声明感知解析、名称解析、已检查精化、逻辑基础清单、公理/定义实例化。

**接口：** `trait LogicBackend`，包含 `elaborate`、`available_actions`、`apply`、`check` 方法。

**包含：** Pure/HOL 精化器、类型推断、排序检查、`LogicBasis` 清单、公理模式重放。

**不得：** 直接构造 `TrustedTheorem` 值。所有定理构造必须通过 Layer 0。

### Layer 2：文档与证明运行时

无头、编辑器无关的引擎，管理文档版本、增量更新、依赖图、诊断、取消、语义标记、证明快照、目标和 fork/rollback/replay。

**接口：** `trait DocumentEngine` 和 `trait ProofSession`。

**不得：** 依赖任何特定编辑器、IDE、AI 框架或协议。

### Layer 3：适配器

将 ISIP 语义映射到特定客户端协议的薄协议适配器。

**包含：** LSP 适配器、MCP 适配器、A2A 适配器、CLI 适配器、Native SDK。

**不得：** 拥有证明状态、构造定理或做出信任决策。适配器仅转换请求/响应。

## 3. 依赖方向

依赖**必须**严格向下流动。禁止 Layer 0 依赖任何更高层，禁止 Kernel 依赖 MCP、LSP、A2A、JSON-RPC、Tokio、HTTP 或 AI。

## 4. 定理权限

外部客户端可以提交：引用、候选动作、候选推导、候选证书。

**不得**提交：`TrustedTheorem` 令牌、`KernelThm` 值、已认证项/命题值、理论扩展权限。

所有外部标识符均为查询引用，绝不构成定理能力。

## 5. 推测执行

运行时可以在隔离分支中执行证明动作。推测分支**不得**扩展可信理论。推测结果在验收前**必须**重放或证书检查。

## 6. 一致性

实现可以声明 ISIP-000 一致性，如果它：

1. 具有明确边界的 TCB 并记录依赖
2. 强制层级依赖方向
3. 分离稳定代码与实验代码
4. 不允许外部客户端构造定理值
5. 对可信制品要求内核验收（而非仅试验成功）
6. 区分推测状态与已验收理论扩展
