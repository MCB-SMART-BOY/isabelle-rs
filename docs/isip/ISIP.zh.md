# ISIP：Isabelle 结构化交互与证明标准

**版本：** 草案 0.1
**状态：** 设计文档 — TCB 闭合前不实现运行时。
**权威参考：** `AGENTS.md`、`docs/ADRs/`、源代码。

## 概述

ISIP 是一套面向编辑器无关、模型无关、传输无关的证明交互标准族。其目标是为现代证明工程平台定义语义模型、运行时行为、证据格式、线协议和集成规范，使人类开发者、IDE、AI Agent 和自动化证明器能够通过单一无头运行时协同工作。

ISIP 不是单一的 RPC 协议，而是一个分层规范体系。

## 七大规范

| 规范 | 标题 | 范围 |
|------|------|------|
| **ISIP-000** | 架构与可信边界 | 系统分层、TCB 定义、依赖方向 |
| **ISIP-100** | 语义模型 | DocumentRevision、ProofSnapshot、Goal、Fact、Action、Transition |
| **ISIP-200** | 运行时模型 | 状态生命周期、分支、推测执行、取消、租约 |
| **ISIP-300** | 证据与信任模型 | 证明轨迹、证书、内核验收、oracle/admit、信任策略 |
| **ISIP-400** | 线协议 | JSON-RPC 2.0 方法、通知、错误码、能力协商 |
| **ISIP-500** | 集成规范 | LSP、MCP、A2A、Native SDK、CLI/CI 映射 |
| **ISIP-600** | 安全与一致性 | 权限、沙箱、审计、威胁模型、兼容性等级 |

### 依赖方向

```text
ISIP-500 集成层（LSP, MCP, A2A, CLI, Native）
    ↓ 依赖于
ISIP-400 线协议
    ↓ 依赖于
ISIP-200 运行时 + ISIP-300 证据
    ↓ 依赖于
ISIP-100 语义模型
    ↓ 依赖于
ISIP-000 架构 + 内核 TCB
```

**关键规则：** 内核（Layer 0）**不得**依赖 ISIP、MCP、LSP、A2A、JSON-RPC 或 AI。所有 ISIP 规范描述的是内核**之上**的内容，绝不侵入内核。

## 分层架构

```text
┌─────────────────────────────────────────────────────┐
│ IDE │ AI 主机 │ 多 Agent │ CLI/CI │ Web/Cloud       │
├─────────┬──────────┬──────────┬──────────┬───────────┤
│   LSP   │   MCP    │   A2A    │ ISIP-CLI │ Native SDK│  ← ISIP-500
├─────────┴──────────┴──────────┴──────────┴───────────┤
│                    ISIP-Wire                         │  ← ISIP-400
├─────────────────────────────────────────────────────┤
│              ISIP 运行时与语义                        │  ← ISIP-100/200
│  文档运行时 │ 证明运行时 │ 搜索运行时                   │
│  分支运行时 │ 制品运行时 │ 信任服务                     │
├─────────────────────────────────────────────────────┤
│              逻辑后端 / 精化                          │  ← ISIP-300
│  Pure/HOL │ DTT │ 分离逻辑 │ SMT/SAT 检查器           │
├─────────────────────────────────────────────────────┤
│          密封内核 API / 证书检查器                     │  ← ISIP-000
└─────────────────────────────────────────────────────┘
```

## 身份模型

ISIP 区分四类身份：

| 类别 | 示例 | 属性 |
|------|------|------|
| **内容身份** | `TheorySnapshotId`, `TrustedArtifactId` | 不可变，由规范内容计算 |
| **运行时句柄** | `ProofSnapshotHandle`, `TaskId` | 会话内有效，不透明，非持久 |
| **可变引用** | `BranchId`, `SessionId` | 指向当前内容身份 |
| **外部引用** | JSON-RPC 中的 `"thm:abc"` | 仅查询，不授予定理权限 |

## 信任模型

核心公式：

```text
权威快照
    +
类型化动作
    ↓
推测性转换 + 状态差异 + 信任增量
    ↓
选中的证据
    ↓
独立检查（重放或证书验证）
    ↓
内核验收的制品
```

ISIP-300 定义四个子模型：
- **逻辑依赖：** 使用的公理、定义、定理
- **来源追溯：** 方法、求解器、Agent、源版本
- **信任负担：** admit、oracle、未检查的外部结果
- **证据状态：** 证书、推导重放、内核验收

## 六条规范性要求

1. **内核不得依赖 ISIP、MCP、LSP、A2A 或 AI。**
2. **外部标识符不得构成定理权限。**
3. **推测状态不得直接扩展可信理论。**
4. **StateDiff 不得作为状态的权威表示。**
5. **搜索可以是不确定的，但选中的证据必须可独立检查。**
6. **跨逻辑复用必须要求显式的翻译证据。**

## Isabelle-rs 实施阶段

ISIP 实施在 TCB 闭合（`KernelTrustedClosed: 1/125`）之前**仅为设计文档**。

| ISIP 阶段 | 前置条件 | 内容 |
|-----------|---------|------|
| **阶段 0（当前）** | 无 | ISIP-000 ADR、ISIP-100 语义草案、ISIP-300 身份草案 |
| **阶段 1：可观察** | TCB 闭合 | `proof/getSnapshot`、`proof/getGoals`、诊断 |
| **阶段 2：事务式** | 阶段 1 | `LogicalAction`、`StateTransition`、`StateDiff` |
| **阶段 3：分支+Agent** | 阶段 2 | `fork`、`moveHead`、`tryBatch`、预算、MCP Profile |
| **阶段 4：证据感知** | 阶段 3 | 推导重放、证书检查、制品持久化、理论扩展 |
| **阶段 5：多逻辑** | 阶段 4 | 第二逻辑后端、TranslationEvidence、A2A Profile |

详见 [ROADMAP.md](../ROADMAP.md) 了解 TCB 主线（在 ISIP 实施之前）。

## ISIP 不管辖的内容

- 内核内部数据结构
- `accept_closed_theorem` 的实现方式
- 表示定理的 Rust 类型
- AI 模型选择或训练
- Isar 语言语法
- 具体证明方法实现
- 构建系统或包管理
