## Historical Category Meanings

| Category | Meaning | Preferred action |
|---|---|---|
| `proof_state_local_assumption` | checked local assumption theorem `A |- A` | retain as Strict *open* proof input; discharge only through a real derivation |
| `proof_state_goal_obligation` | historically `have`/`show`/`obtain` obligation scaffolding | `have`/`show` now validate actual proof results before successful export; review any remaining compat request carriers separately |
| `fallback_should_admit` | unsupported feature or failed proof accepted as theorem | fail or classify as explicit admission at the recovery boundary; never promote to a proved theorem |
| `parser_loader_debt` | parsed/generated term lacks strict certification or name/type resolution | keep independent search data untrusted; complete-source loader rejects unsupported declarations and incomplete proofs |
| `test_fixture` | unit/property/integration test scaffolding | migrate high-value kernel tests to checked fixtures; keep compat tests only when testing compatibility behavior |
| `hol_bootstrap` | generated HOL/bootstrap/package facts without a real kernel derivation yet | design trusted bootstrap/definition package or admit/classify stubs |
| `tactic_intermediate` | proof-search, conversion, simplifier, or automation intermediate theorem shape | keep outside trusted table; migrate toward typed proof-state constructors and `Result` errors |
| `unknown_needs_review` | call site not classified by this pass | inspect before any migration |

## Historical Observations And Current Corrections

- The largest compatibility debt is HOL/bootstrap generation, not the strict
  kernel itself.
- No obvious `fallback_should_admit` site was changed in this pass. The sampled
  method fallback paths already use classified `admitted:*` reasons.
- `src/isar/method.rs` is intentionally left as mixed: it contains proof-state
  setup, method tests, and theorem-shape construction. It should be migrated by
  hunk, not by whole file.
- `_compat` usage in tests is not automatically wrong. Kernel-facing tests
  should migrate to checked fixtures when they are testing trusted behavior;
  tests that characterize legacy behavior should keep `_compat` explicit.
- First test-fixture migration pass moved `src/core/proofterm.rs`, the
  trusted-path parts of `src/core/thm.rs`, and most of
  `tests/kernel_soundness.rs` to checked CTerms plus strict `ThmKernel`
  constructors. Remaining `tests/kernel_soundness.rs` `_compat` calls
  intentionally test compatibility taint and trusted-table rejection.
- Second test-fixture migration pass moved `tests/proptest.rs` kernel property
  scaffolds and `tests/integration_tests.rs::test_kernel_15_ops` to checked
  fixtures. Remaining `tests/integration_tests.rs` `_compat` calls are legacy
  TPTP/pretty-printer export tests over HOL/dummy syntax, not strict-kernel
  coverage.
- At the time of this scan, `ProofState::assume` and `Goal::init` moved to
  checked propositions and strict *open* assumption theorems. That did not
  make fresh goal obligations into finished proofs.
- Since this scan, both `ProofState` and `IsarProof` retain actual method/show
  results, reject missing/unconnected results at `qed`/`done`, validate the
  complete expected proposition and allowed hypotheses, and discharge only
  real local assumptions/fixes (`src/isar/proof_result.rs`). `have`/`show`
  cannot authorize a lemma merely by creating a compatibility-shaped goal.
- The legacy public `parse_term` now requires full consumption, while the
  separate `parse_term_with_status` keeps explicitly incomplete diagnostics
  for search only. The complete-source `TheoryProcessor` fails on unsupported
  declarations and incomplete proof blocks rather than exporting a partial
  theory.
- Some compatibility calls still serve as *request carriers* or search
  intermediates; for example the Metis/Meson tactic facades start with a
  non-evidence request. Final successes require exact full-proposition
  `validate_proof_result` checks and valid strict derivations. The audited
  sampled `HOL::TrueI` projection now reaches exact-owner strict kernel
  acceptance, without turning these compatibility calls into trusted evidence.

## Migration Order

1. Retain taint: `_compat` results remain `ThmTrust::Compat`, never proof
   evidence solely because they are oracle-free.
2. Preserve the accepted sampled `HOL::TrueI` boundary while extending
   source-faithful migration to other lemmas; neither compat search nor legacy
   Strict results can be promoted to `KernelTrustedClosed`.
3. For each remaining consumer, distinguish request/search scaffolds from
   actual result validation. Repair a false-success path with a checked
   derivation or explicit failure/admission, not a changed status label.
4. Audit broad HOL/bootstrap packages separately; do not infer trust from
   this dated constructor-frequency inventory.
